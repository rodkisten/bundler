Language surface
Every branch
has a button.

          
The cards below load executable examples into the playground. Together they cover the documented Cipó language primitives, compatibility syntax, smart helpers and browser runtime modes.

        

        

      


      

        
01 / ARTIFACTS
Atomic, sheet, inline, scoped and layered.
The same value pipeline can emit class artifacts, full stylesheets, inline declarations, scoped sheets and cascade-layer sheets.
css`` · atomic.css`` · sheet.css`` · inline.css``

        
02 / TOKENS
$, $$ and var() know who owns what.
Theme tokens, Cipó runtime custom properties and host-owned CSS variables keep separate contracts, with derived math and fallback chains.
$brand · $$progress<number> · var(--host)

        
03 / STATE DSL
Fábrica state becomes observable CSS.
Data states, booleans, slots, group, peer, variant and compound selectors all lower to standards-based selectors.
state() · slot() · group() · peer() · variant()

        
04 / RESPONSIVE
Viewport and container contexts share one grammar.
Breakpoint objects, x-context chains, negated breakpoints, named containers and literal container bounds stay next to the declaration they affect.
x:md:hover · x:not(md) · x:cq(card >= md)

        
05 / DEEP HELPERS
Typography, motion and layout are composable.
text(), fluid(), motion(), stack(), cluster(), center(), cover(), sidebar() and interaction helpers lower into native CSS primitives.
text(fluid(14px,20px) / 1.5) · motion($enter)

        
06 / EXTENSIBILITY
Plugins without surrendering CSS.
Register aliases, helpers, properties, variants, native functions, config presets and config plugins, then inspect and benchmark the resulting artifacts.
registerHelper() · recipe() · explainDetailed()

Build-time surface
Same vine,
earlier in time.

          
The browser cannot run Vite inside this page, so the build-only package exports are represented as concrete integration examples. They use the same compiler semantics as the runtime playground.

        

        

          
@rodkisten/cipo/compiler
Compile Cipó source ahead of time while preserving the same AST, selector, token and DSL rules.
import { compileCipoSourceBuild } from "@rodkisten/cipo/compiler";

const result = compileCipoSourceBuild(source, options);
// Build artifact: standards-based CSS.

          
@rodkisten/cipo/vite
Use the Vite integration for whole-build styled extraction, Fábrica compilation, atomic promotion and config lowering.
import { cipoVite } from "@rodkisten/cipo/vite";

export default {
  plugins: [cipoVite({
    configCss: "./cipo.config.css"
  })]
};

          
Compiled runtime
Production can consume parser-free configuration payloads and precompiled style artifacts instead of redoing static work in the browser.
import {
  configureCompiledCssConfig
} from "@rodkisten/cipo/compiled-runtime";

          
Runtime inline
The inline-oriented entry keeps styled component styles on the runtime inline path for environments that prefer style attributes.
import {
  compileInlineCss
} from "@rodkisten/cipo/runtime-inline";

        

      


      

        

          
Plant it anywhere

          
One script.
A lot of leaves.

          
Use the browser bundle directly in a userscript or consume the package API in an application. Every executable demo on this page runs against the same published IIFE generated by this repository.

        

        
<script src="../cipo.iife.js"></script>
<script>
  Cipo.configureFromCss(`
    @theme { colors: (brand: #b9ff66); }
  `);

  const card = Cipo.atomic.css`
    glass;
    px: 4;
    bg: alpha($brand / 18%);
  `;
</script>
